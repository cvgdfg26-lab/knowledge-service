# 联调配置清单

按当前代码与 `.env.cpu.example`、`.env.gpu.example` 整理。先填写第 1 节即可确定部署方式；缺少的软件版本、模型快照等可注明“待确认”，再在已授权的服务器上检查。

服务器地址、用户名、目录、模型版本等普通配置可以回复到聊天中。API Key、服务 Token、登录密码与 SSH 私钥保留在本地配置或密钥文件，只告知存放路径和是否已填写；不要把完整 `.env` 贴到聊天中。

## 1. 首先提供的信息

| 项目 | 需要的内容 | 用途 |
|---|---|---|
| CPU 服务器连接 | SSH 地址、端口、用户名；直连/跳板机/VPN；已有 SSH 别名或本地私钥路径 | 连接与部署业务服务、数据库 |
| GPU 服务器连接 | 同上；若与 CPU 同机，注明共用 | 部署或联调两个模型服务 |
| 两端系统与资源 | 操作系统、CPU 架构、CPU 核数、内存、可用磁盘；GPU 型号、数量、每卡显存 | 核对镜像、资源限额与模型分配 |
| 使用权限 | 是否有 Docker 执行权限、是否可使用 sudo；允许使用的部署目录/数据盘目录 | 确定安装、容器与持久卷方案 |
| 已有环境 | Docker/Compose 是否可用；GPU 驱动/容器运行时是否安装；是否已有模型或数据库服务 | 决定新部署或复用，不重复初始化已有环境 |
| 两端网络 | CPU 能否访问 GPU 私网地址；允许的 GPU 服务端口；是否存在出站代理/访问限制 | GPU 调用、拉取镜像/依赖、访问厂商 API |
| 页面访问方式 | SSH 隧道，或私网/公网域名；是否已有 HTTPS 代理 | 配置入口、来源、主机名与 Cookie |
| 联调范围 | 仅连接检查，或包含部署/初始化、GPU 推理、厂商生成、MinerU 解析 | 明确下一轮要执行哪些操作 |

上述端口是连接/入口信息。默认存储组件只在 CPU 容器网络内通信，无需为 MongoDB、Milvus、MinIO、etcd、Neo4j 开放公网端口。

## 2. GPU 模型配置

| 配置项 | 填写位置 | 需要说明 |
|---|---|---|
| `BGE_MODEL_PATH` | GPU 主机 `.env.gpu` | 完整 BAAI/bge-m3 快照的绝对目录；没有下载则注明“未准备” |
| `BGE_MODEL_REVISION` | 两端环境文件 | 实际模型快照的 revision/commit；两端一致，不填写任意占位版本 |
| `BGE_GPU_ID` | GPU 主机 `.env.gpu` | 分配给嵌入服务的 GPU ID |
| `BGE_M3_SERVICE_URL` | CPU 主机 `.env.cpu` | CPU 可访问的服务根地址，例如 `http://<GPU私网IP>:8100`，不附加 `/v1/embeddings` |
| `BGE_SERVICE_TOKEN` | 两端环境文件 | 同一专用 Token；可以沿用本地 `.env.cpu` 已生成的值，GPU 服务要求至少 24 字符 |
| `RERANKER_MODEL_PATH` | GPU 主机 `.env.gpu` | 完整 BAAI/bge-reranker-large 快照绝对目录 |
| `RERANKER_MODEL_REVISION` | 两端环境文件 | 实际重排模型快照 revision/commit，两端一致 |
| `RERANKER_GPU_ID` | GPU 主机 `.env.gpu` | 重排服务 GPU ID；若与嵌入共享，说明还有哪些进程占用显存 |
| `RERANKER_SERVICE_URL` | CPU 主机 `.env.cpu` | 服务根地址，例如 `http://<GPU私网IP>:8101`，不附加 `/v1/rerank` |
| `RERANKER_SERVICE_TOKEN` | 两端环境文件 | 同一专用 Token；可以沿用本地已生成的值，至少 24 字符 |
| `GPU_BIND_IP` | GPU 主机 `.env.gpu` | 默认是 `127.0.0.1`；跨主机直接连接时需设为对应私网接口地址，或说明使用隧道/代理 |

嵌入模型已固定为 BGE-M3，1024 维稠密与学习型稀疏；不需要再选嵌入厂商、其他模型或维度。若 GPU 推理服务已经部署，只需提供可达根地址、真实模型版本、鉴权配置存放位置和现有接口说明；模型文件目录与 GPU 分配仅在需要部署/调整服务时填写。

## 3. 外部 API

| 项目 | 普通信息 | 密钥填写位置 | 首次联调条件 |
|---|---|---|---|
| 生成模型 | 默认 DashScope / qwen-flash；告知实际账户区域、可用模型、是否使用默认兼容地址 | CPU `.env.cpu` 的 `LLM_API_KEY` | 需要生成回答时填写；仅检索可暂不填写 |
| MinerU | 账户是否可用、当前上传/解析是否有额度；解析模式按项目默认或说明特殊要求 | CPU `.env.cpu` 的 `MINERU_API_TOKEN` | 需要解析 PDF/DOCX 时填写；MD/TXT 导入可暂不填写 |
| MinerU 传输域名 | 当前账户 API 返回的上传地址、结果下载地址中的**准确主机名** | CPU `.env.cpu` 的 `MINERU_TRANSFER_HOSTS`，JSON 数组 | 留空会拒绝传输；不需要把含签名参数的完整 URL 发到聊天中 |
| API 调用范围 | 允许调用哪些 API、联调最大次数或费用上限、可外发的样例资料 | 回复普通说明即可 | 便于控制联调成本与样例范围 |

如果暂时不知道 MinerU 传输域名，可以先注明“待确认”，后续从已授权的实际 API 返回中提取并核对。

API 配置完整后，还需要由知识库管理员分别打开 `allow_llm_egress` 和 `allow_parser_egress`；配置密钥不会自动开放资料外发。

当前 CPU Compose 使用默认 DashScope 兼容地址，并固定 `qwen-flash`；它只传入生成密钥。若改账户区域、生成地址/模型或 MinerU 地址/解析模式，请先告知普通参数，我会同步补充 Compose 环境变量映射；仅在 `.env.cpu` 中添加未映射的变量不会改变容器内配置。

## 4. 网关与环境

| 配置项 | 如何确定 |
|---|---|
| `APP_ENV` | 首次开发联调通常用 `dev`；真实预发布使用 `staging` |
| `CPU_BIND_IP` | 隧道访问可保持环回；直连私网入口需指定 CPU 私网接口地址 |
| `ALLOWED_ORIGINS` | 浏览器实际来源的完整协议、主机、端口，例如 `https://kb.example.com`；JSON 数组 |
| `TRUSTED_HOSTS` | 浏览器入口的主机名/IP，不含协议或路径；JSON 数组 |
| `COOKIE_SECURE` | `staging/prod` 必须为 `true`，需 HTTPS 入口 |
| HTTPS | 已有反向代理入口及可复用的证书文件路径，或注明需要配置；证书私钥不发聊天 |

当前网关为 HTTP 开发配置；告知入口方式后再调整实际部署配置。已有 SSH 隧道可以作为首次联调入口，不必提前购买域名。

## 5. 新建存储与复用存储

**全新部署**：不需要手工提供各数据库的地址/端口。Compose 已声明内部 DNS、业务数据库、bucket 与 collection；本地 `.env.cpu` 和 `infra/secrets/mongo-key` 已生成随机初始化凭据。将配置安全放到对应 CPU 主机，不要重复生成或覆盖已投入使用的密码。

已生成的密码范围为 `MONGO_*_PASSWORD`、`MINIO_*_PASSWORD`、`MILVUS_*_PASSWORD`、`NEO4J_PASSWORD` 与 `SEED_*_PASSWORD`。这些是新部署的配置材料，不表示服务器上的账户或数据库已经初始化。`.env.gpu` 仍需依据模板准备，并与 CPU 配置对齐 Token/revision。

**复用已有服务**：按实际复用的组件提供下面的信息，秘密仍放入本地环境文件。

| 服务 | 普通配置 | 本地秘密 |
|---|---|---|
| MongoDB | 可达地址、版本、副本集名、业务数据库名、checkpoint 数据库名、认证库、服务用户名、是否启用 TLS | 各服务的连接 URI/凭据；URI 中的密码不发聊天 |
| Milvus | 地址、版本、collection、Schema、generation、现有数据使用的 BGE 快照 | Token/服务账户密码 |
| MinIO | Endpoint、TLS、原文/派生/图片 bucket、业务账户与 Milvus 内部 bucket 的安排 | access key / secret key |
| Neo4j | Bolt 地址、版本、database、用户名 | 密码 |

同时注明是否已有必须保留的数据、可以创建的隔离数据库/bucket/collection，以及现有服务是否已设置好专用账户。复用环境需要调整当前 Compose 的服务连接与账户映射，不能直接套用新环境的初始化命令。
