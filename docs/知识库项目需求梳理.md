# 多业务线知识服务平台需求说明

文档状态：需求设计。业务场景、容量和服务指标为规划与验收依据；实现状态及运行结果由后续测试和发布记录维护。

## 1. 业务背景与建设目标

### 1.1 业务场景

平台面向具有听书、教育、旅游、育儿、金融五条内容业务线的机构，服务内部编辑、教研、运营、客服与研究人员。各团队通过统一入口维护和查询本领域资料，跨部门共享受权限控制的公共资料。

业务场景定义如下：图书简介、课程资料、旅游信息、育儿内容和金融文档分别由业务团队维护，资料格式和更新周期不同。员工需要从多份文档中查找依据、回答问题并核对版本。系统通过统一资料治理与检索增强问答，支持这一工作流程。

### 1.2 需要解决的问题

- 资料分散：不同文件与目录缺少统一检索入口。
- 查询成本高：精确术语检索和自然语言查找需求并存。
- 版本难区分：旧课程、过期旅游信息和历史政策可能被误用。
- 答案难核对：结论缺少可定位的来源，跨文档整理容易遗漏条件。
- 资料维护不闭环：发布、纠错、下架和反馈缺少统一流程。
- 权限边界不清：业务线内部资料不能因问答或引用而泄露给其他人员。

以上是本项目设定的业务问题。减少查询时间、提高客服答复效率等业务收益，需在实际试点中通过基线和使用记录验证。

### 1.3 项目目标

建设一个具备资料导入、审核发布、版本管理、混合检索、带来源问答、权限隔离和运营维护能力的知识服务平台。

业务闭环：内容维护 → 解析检查 → 业务审核 → 索引发布 → 用户查询 → 查看依据 → 问题反馈 → 内容或系统修订。

质量目标：信息可追溯、权限可验证、更新可控、异常可恢复、效果可评估、运行可观测。

## 2. 用户角色与访问边界

| 角色 | 工作职责 | 访问与操作范围 |
| --- | --- | --- |
| 普通知识使用者 | 搜索、问答、查阅来源、提交反馈 | 仅访问被授权的知识库与已发布文档 |
| 内容维护者 | 上传、编辑元数据、提交审核、修订资料 | 所属业务线的授权资料；不能自行发布其提交的内容 |
| 业务审核者 | 校验内容、批准发布、退回修改、紧急下架 | 所属业务线的审核范围 |
| 知识库管理员 | 创建知识库、配置成员与业务规则 | 被授权的知识库管理范围 |
| 系统运维人员 | 部署、监控、故障恢复、配置管理 | 运维权限不默认授予业务原文阅读权限 |

首期服务单一机构，支持业务线和知识库隔离。多机构租户模式列入后续范围。

权限要求：

- 身份由后端认证，知识库和文档权限由后端执行；前端传入的领域、用户标识或角色不能直接作为授权依据。
- 角色用于确定操作权限，知识库成员及文档可见范围用于确定数据权限；默认拒绝未授权访问。
- 权限适用于搜索、问答、原文预览、下载、历史会话、缓存和调试数据。
- 内容提交者与审核者采用不同身份；越权发布和修改授权均记录审计事件。
- 跨业务线检索只能在用户有权访问的范围内进行；是否启用由知识库管理员配置。
- 离职、角色变更或撤销权限后，后续请求立即重新校验，缓存和历史会话不能继续暴露被撤销的资料。

## 3. 领域知识需求

| 领域 | 资料范围 | 典型用户问题 | 必要业务字段 | 回答与维护规则 |
| --- | --- | --- | --- | --- |
| 听书 | 图书简介、书籍元数据及明确授权的补充资料 | 一本书讲什么？哪些书涉及某主题？ | 书名、作者、分类、适用人群、来源 | 简介不能支持具体原文章节时说明资料不足 |
| 教育 | 课程资料、课程文档、教学项目文档 | 某课程有哪些前置要求？某项目交付什么？ | 课程、阶段、章节、知识点、版本、适用对象 | 明确课程版本；跨章节综合保留适用条件 |
| 旅游 | 交通、景点、线路、美食、酒店 | 某地有哪些交通方式？给定资料下如何安排线路？ | 城市、地点、类别、时间、有效期、核验日期 | 标明资料时间；不承诺实时价格、营业状态或库存 |
| 育儿 | 专家建议、亲子案例、话术、科普 | 某年龄段的沟通场景有哪些参考？ | 年龄段、场景、作者、内容类型、适用条件 | 区分案例与一般建议；案例发布前处理可识别信息 |
| 金融 | 年报、基金说明、政策、FAQ、风险揭示 | 某年度数值是多少？某版本规则是什么？ | 机构、产品、年度、地区、发布/生效时间、单位 | 引用原始期间与单位；不提供收益承诺与交易执行 |

教育作为首批试点业务线，验证完整流程后分批接入其余领域。金融首批覆盖文字资料和可人工核对的简单表格，复杂跨页表格单独验收。

资料时效由业务线定义：课程跟随版本；旅游按资料有效期和核验要求；政策跟随生效与失效时间。无法确认有效性的资料标记待核验，不能作为确定的当前信息回答。

## 4. 系统范围与发布优先级

P0 表示受控试点上线必须具备的能力；P1 表示扩大使用范围时按需求建设；P2 暂缓。

### 4.1 P0：受控试点范围

1. 身份认证、基础角色、业务线/知识库/文档权限和审计。
2. Markdown、TXT、文字型 PDF、DOCX 导入与解析预览。
3. 内容审核、发布、版本更新、下架、删除与失败重试。
4. Milvus 稠密与 BGE-M3 稀疏混合召回、独立 BM25 基线、GPU 重排与元数据过滤。
5. LangGraph 编排的流式问答、证据引用、资料不足与冲突处理、有限追问与 MongoDB 检查点。
6. 异步处理任务、幂等控制、增量更新和发布一致性。
7. 反馈工单、独立调试视图、离线评估与回归测试。
8. 超时、限流、故障降级、运行监控、备份恢复和发布回滚。
9. 开发、测试、运行环境隔离及部署说明。
10. Neo4j 基础图谱：知识库、文档版本、片段及课程/章节/知识点关系均保留来源；基础图谱就绪纳入发布检查。

### 4.2 P1：扩展范围

- 企业身份系统集成、细粒度权限与多机构租户隔离。
- 经独立验证的 MinerU 扫描件 OCR、复杂表格、受控网站/业务系统同步。
- qwen3-vl-flash 受控图片/图表理解，图片由文本证据关联；图片向量检索另行设计。
- 查询改写、复合问题分解、工具调用、自动领域路由。
- 缓存优化、模型路由、本地推理与更高并发扩容。
- 更完善的运营报表、内容覆盖分析、过期资料批量治理。
- Neo4j 受控关系扩展与自动实体/关系抽取；逐跳授权、证据核对与图谱辅助检索独立评估。

### 4.3 P2：非本项目核心范围

音频播放、配音、课程交易、酒店预订、金融交易、实时行情、通用多模态平台和模型预训练。

系统提供资料查询与基于证据的辅助回答。需要实时信息或外部动作时，新增接口、权限和独立验收，不由模型自行补造。

## 5. 核心功能需求

### 5.1 知识库与资料治理

- 维护知识库名称、业务线、描述、成员、负责人、资料类型、时效规则和模型配置。
- 文档记录来源、责任人、版本、访问范围、发布时间、生效/失效时间与内容摘要。
- 支持单个及批量导入，显示任务进度、失败原因和重试入口。
- 上传限制文件大小、类型和批量数量；解析任务限制资源和时间，异常文件不阻塞其他任务。
- 解析预览显示正文、标题、表格与原文位置；维护者修订后提交审核。
- 发布仅允许使用解析通过、审核通过、索引准备完成的版本。
- 资料不足、重复、过期、来源缺失等情况可形成维护任务。
- 无法解析的表格或图片明确标记，不能静默遗漏后仍宣称已完整入库。

### 5.2 状态与版本

内容状态和处理状态分别维护：

- 内容状态：草稿、待审核、已退回、审核通过待发布、已发布、已下架、已归档、已删除。
- 处理状态：待处理、处理中、成功、失败、取消；独立记录解析、切分、索引任务结果。

审核通过不等于已发布。索引未就绪时不对用户开放新版本。

每份文档可有多个不可混淆的版本。更新创建新版本并沿用审核流程；旧版本在新版本发布前继续有效，新版本发布后默认退出当前检索范围。历史查询须明确版本或时间范围，且重新校验权限。

下架立即阻止新请求使用该资料，后台清理索引和缓存；删除进一步按数据保留规则清理原文、片段、向量和相关副本。审计可保留操作元数据，不继续保留被删除的业务正文。

### 5.3 检索

- 支持关键词、自然语言及必要业务字段筛选。
- 查询先确定身份、授权知识库、文档可见范围和有效版本，再执行召回。
- 稀疏和向量检索分别可运行，混合融合与重排参数可配置。
- 检索候选在进入重排、模型上下文前再次核对权限、发布状态和版本。
- 不因索引更新延迟而将下架、删除或未发布资料作为有效证据。
- 返回标题、片段、原文位置、版本、来源和更新时间。
- 未授权资料的标题、数量、片段和相似度不通过结果、错误或调试界面泄露。

### 5.4 问答与引用

- 默认在所选知识库回答；跨库查询必须显式选择且有权限。
- 关键事实、数字、规则和建议附对应证据，能够打开原文位置。
- 引用标识由系统提供并校验，拒绝不存在或越权的来源标识。
- 资料不足时说明可回答范围；必要条件缺失时澄清；资料冲突时指出差异及适用条件。
- 不将检索分数直接展示为答案正确概率。
- 支持流式输出、取消和阶段状态；网络中断后显示明确状态，重试不重复计入同一次反馈或工单。
- 有限追问采用有上限的历史窗口，保存原始问题和用于检索的问题；切换知识库后重新建立证据范围。
- 历史回答记录使用过的文档版本和时间，打开历史引用时检查当前权限；历史答案不自动代表当前有效结论。
- 权限撤销、敏感资料删除后，相关历史回答必须隐藏或重新生成；不能只禁用引用链接而继续展示泄露的正文。
- 文档内容视为证据，不作为改变授权范围、系统规则或触发工具的指令。

### 5.5 反馈与运营

- 用户可反馈答案错误、引用错误、资料过期、资料缺失和无关结果。
- 反馈关联 request_id、问题、文档版本和相关链路记录；可按权限选择是否保存原文。
- 业务问题分派内容负责人，系统问题分派技术负责人，记录处理结果和回归验证。
- 运营查看使用量、失败率、覆盖缺口和待更新资料；报表只能访问其授权范围。
- 技术人员通过受限调试视图定位召回、融合、重排、上下文和生成问题。

## 6. 处理流程与数据一致性

### 6.1 离线流程

kb-import:8000 上传至 MinIO → 文件校验与解析外发检查 → MongoDB 持久化任务 → Worker / LangGraph 调用 MinerU API → 下载并保存解析产物 → 清洗切分与基础图谱草稿 → 预览与审核 → GPU BGE-M3 编码 → Milvus / Neo4j 准备 → MongoDB 发布指针切换 → 缓存失效。

要求：

- 文档、版本、片段和处理任务有稳定标识；内容摘要用于辅助去重。
- 保留章节路径及必要上下文；PDF 使用页码，Markdown/TXT 使用标题或行号，不虚构定位信息。
- 重试、重复投递和进程重启不重复创建已完成的索引与版本。
- 任务有超时、有限重试、失败隔离和人工重跑；记录执行阶段与错误原因。
- 元数据持久化与任务投递存在可靠补偿或事务事件记录，避免数据库成功而任务永久丢失。
- 当前检索 Profile 的稠密、BGE 稀疏与 BM25 通道及可检索性均准备成功后才切换有效版本；任何一侧失败时继续使用旧版本并提示维护者。
- 基础图谱事实绑定原文证据、版本和代际，graph manifest 验证成功才发布；任何必要副本失败不切换，跨 MongoDB/Milvus/Neo4j/MinIO 不假设共享事务。
- MinerU 不自部署，采用外部异步 API；提交、轮询、产物下载分别记录，重启优先恢复已有远程任务，未知提交不盲目重复。Markdown/TXT 可本地解析，禁止外发的 PDF/DOCX 在提交前阻断。
- 更新、下架、删除、权限变更触发缓存失效，定期核对数据库、索引与存储的一致性。

### 6.2 在线流程

kb-query:8001 / LangGraph 问答图：认证与 MongoDB 授权 → 查询范围和当前版本 → GPU BGE-M3 查询编码 → Milvus 混合召回 → 再校验候选 → 可选 Neo4j 关系扩展与证据复核 → GPU BGE-Reranker-Large → 上下文预算 → 厂商大模型 API 生成 → 引用校验 → MongoDB 答案与检查点。

- 一次请求记录使用的数据版本、索引版本和模型配置。
- 普通版本切换允许请求使用启动时的有效快照并标明来源版本；权限撤销与紧急下架属于即时限制，不能依赖旧快照继续输出。
- 需要即时撤销时停止相关流式输出，并对会话中的已有敏感内容执行隐藏或清理。具体并发边界通过测试验收。
- 生成失败可降级为授权资料检索结果，明确告知问答暂不可用；该降级不计作生成成功。

### 6.3 缓存边界

若启用缓存，键包含授权范围或可验证的权限签名、知识库、有效资料版本、问题及模型/提示词配置。每次返回缓存前重新校验访问范围；权限变化和资料变更主动失效。首期允许不缓存生成答案，优先保证正确性。

## 7. 架构与工程要求

采用导入与查询分离的双服务架构：kb-import:8000 与 kb-query:8001 独立容器，复用公共认证、Schema 和业务包；后台任务由独立 kb-worker 执行。

逻辑组件包括：用户与管理入口、API 服务、认证授权、资料处理任务、元数据数据库、原文存储、稀疏索引、向量索引、重排、生成模型适配、评估和运行监控。

### 7.1 技术栈与职责

| 类别 | 技术选型 | 配置与职责 |
| --- | --- | --- |
| 后端 | FastAPI + Uvicorn | kb-import:8000 导入/管理；kb-query:8001 查询/问答 |
| 工作流 | LangGraph | 问答、解析与索引图；检查点不代替任务队列 |
| 大语言模型 | 厂商提供的 API，默认 DashScope Qwen | qwen-flash 文本问答；qwen3-vl-flash 为 P1 图片分支，不自部署生成模型 |
| 唯一嵌入 | BAAI/bge-m3 | 1024 维稠密 + 学习型稀疏；文档/查询均调用远程 GPU 服务 |
| 重排 | BAAI/bge-reranker-large | 远程 GPU 服务，超时可回退融合排序 |
| 向量数据库 | Milvus | 稠密与 BGE 稀疏混合检索、独立 BM25 通道 |
| 图数据库 | Neo4j | 实体、关系、原文证据与版本，不代替 MongoDB 授权 |
| Milvus 元数据 | etcd | Milvus 内部依赖，不承载业务结构化数据 |
| 文档数据库 | MongoDB | 对话历史、权限与业务元数据、任务、发布指针、检查点；使用副本集验证事务 |
| 对象存储 | MinIO | 私有原始文件、解析产物与图片；与 Milvus 内部存储隔离 |
| PDF 解析 | MinerU API | 外部异步解析，下载 Markdown/JSON/图片至 MinIO，不部署解析容器 |
| 前端 | HTML5 + CSS + 原生 JavaScript | 无框架 ES Modules、Fetch/SSE 与安全预览 |

唯一检索 Profile 为 `bge1024_bge_sparse`。文档和查询采用同一 BGE-M3 快照、1024 维稠密与相同稀疏输出规范；不调用厂商嵌入模型。快照/预处理变更创建新代际重建，GPU 编码故障仅允许授权 BM25 降级或失败，不换模型。BGE 学习型稀疏不等同于 BM25。

CPU 服务器容器化部署 kb-import、kb-query、kb-worker、MinIO、Milvus、etcd、Neo4j、MongoDB；GPU 服务器容器化部署 BGE-M3、BGE-Reranker-Large。MinerU 解析与大模型生成采用外部 API，均不列入两台服务器的模型部署清单。

两个服务共享 MongoDB 权威会话和授权逻辑，端口不代替权限边界；用户访问可经同源 HTTPS 代理，存储内部端口不直接面向用户。CPU/GPU 两套容器网络通过可路由私网端点连接，不能直接跨主机使用 localhost 或 Compose 服务名。单台服务器布局不等于高可用。

Neo4j 图谱事实保留 kb_id、version_id、generation 与原文证据，不能跨库合并实体后暴露邻居。自动抽取结果先审核再发布，关系扩展逐跳校验范围；图谱不能提供没有原文依据的确定结论。

私有 GPU 仅解决嵌入/重排部署边界。MinerU API 提交前检查解析外发，厂商生成前检查上下文外发。资料不允许进入厂商生成 API 时，只返回授权检索结果或阻止生成；完整私有问答另行选型。解析接口契约见 [MinerU 官方文档](https://mineru.net/apiManage/docs)。

MinIO 保留指定选型；[官方社区仓库](https://github.com/minio/minio)已归档并采用源码分发，工程初始化时需明确可信构建、固定版本与维护支持方式。

### 7.2 工程约束

- 生成、Embedding、重排模型分别配置，记录模型标识、参数、版本和服务依赖。
- 接口定义输入校验、错误码、请求标识、分页和操作幂等要求；敏感接口有审计记录。
- 模型调用有超时、有限重试、并发上限和费用配额；避免层层重试放大费用与压力。
- 过载时限流或进入有界队列，返回可理解的忙碌状态，不无限等待。
- 重排服务失败可回退融合排序并记录降级；生成服务失败回退资料检索；授权或有效版本无法确认时拒绝提供资料。
- 配置和密钥不硬编码；开发、测试、运行环境使用不同凭据与数据范围。
- 依赖锁定、数据库迁移、健康检查、就绪检查、启动和停止流程可复现。
- 关键流程测试涵盖身份隔离、发布一致性、幂等重试、更新与缓存失效、故障降级。
- 技术实现、部署环境与测试记录分别描述，不能用架构图代替已实现能力。
- MongoDB messages 保存业务历史，LangGraph 检查点保存工作流状态；恢复前重新鉴权，检查点不能代替发布状态或自动保证外部调用恰好一次。

## 8. 数据保护与留存

- 文档按公开、内部、敏感等业务等级管理；外部模型调用前检查资料是否允许离开部署环境。
- 未允许外发的原文不进入外部生成、Embedding、重排或自动评估服务；需本地处理或阻止调用。
- 网络传输与持久化存储采用适合部署环境的保护措施；下载链接短时有效并绑定授权。
- 日志默认记录标识、耗时、状态与用量，不记录密钥、完整敏感文档或不必要的个人信息。
- 问答原文是否保存、谁可查看、保留多久由机构策略配置，并提供删除流程。
- 亲子案例和用户材料在发布前检查可识别信息；只上传明确允许使用的材料。
- 删除同时覆盖 MongoDB 历史与检查点/写记录、Milvus 全代际、Neo4j 断言/证据及孤立实体、MinIO 文件/图片及对象版本、缓存和调试副本；备份按保留周期处理。外部解析/生成服务的数据留存与可用删除能力按提供方确认，不能声称本地删除自动删除厂商副本。
- 恢复旧备份后重新应用删除与撤权记录，再开放查询，避免已清理资料重新可见。

本节为系统能力要求。具体保留周期、外部服务范围和数据分级，作为试点上线前必须确认的配置项。

## 9. 容量、性能与可靠性目标

### 9.1 首轮容量假设

用于指导测试的初始目标：100 个授权用户、10,000 份逻辑文档、约 200,000 个片段、20 个并发问答会话。数据规模指目标测试规模，不代表现有业务规模。

真实资料和评估语料用于质量测试；明确标注的合成数据可用于容量测试。不能用重复或合成文档数量宣称真实知识覆盖范围。

所有压测报告记录硬件、资料规模、索引参数、生成模型、答案长度、网络条件、外部服务配额和请求类型。

### 9.2 初始服务目标

| 指标 | 初始目标 | 验证条件 |
| --- | --- | --- |
| 检索与重排 P95 | ≤ 1.5 秒 | 约定数据规模与负载，缓存冷/热结果分开 |
| 问答首字延迟 P95 | ≤ 5 秒 | 固定模型、输入规模和外部服务条件，授权/检索耗时计入 |
| 问答总耗时 P95 | ≤ 30 秒 | 约定输出长度上限，例如 600 汉字；超时和取消单列 |
| 更新生效 | 发布确认后新请求使用新版本 | 发布确认之前旧版本有效，准备失败不得切换 |
| 撤权/下架 | 后续请求授权检查立即生效 | 同时验证缓存、原文、下载和历史会话 |
| 核心问答月度可用性 | 目标 99.5% | 返回正常答案或符合规则的业务拒答；异常降级、超时、过载失败计为失败 |
| 恢复目标 | RPO ≤ 24 小时、RTO ≤ 4 小时 | 根据备份频率与恢复演练验证 |

这些数字是待测试确认的初始工程目标，不是已达成指标或对外合同承诺。若模型配额、部署资源或资料复杂度不满足条件，应在试点发布前调整容量与目标并记录依据。

上线前验证监控和恢复能力；月度可用性必须经过相应观察窗口后才能报告，不以一次压测或健康探针结果替代。

## 10. 可观测性、备份与发布

### 10.1 监控与告警

- request_id 贯穿认证、检索、重排、生成、引用及反馈。
- 监控请求量、错误率、限流、队列积压、任务失败、各阶段时延、Token 用量和费用估算。
- 同时记录空召回、业务拒答、异常降级、失效资料拦截和引用校验失败。
- 模型不可用、队列持续积压、发布失败、存储或数据库故障有告警与处置说明。
- 监控报表和调试信息本身执行权限控制；不通过观测系统扩大资料可见范围。

### 10.2 备份与恢复

- 定期备份 MongoDB 业务与权限数据、MinIO 原文/产物/图谱快照、发布配置和审计；Milvus 及其所需 etcd/内部对象数据按整体恢复方案备份或重建，Neo4j 关系按版本能力备份或从已审核快照重建。
- 记录备份完整性和可恢复性；仅显示备份成功不足以验收。
- 在隔离环境执行恢复演练，验证文档、权限、当前版本、删除记录和检索结果。
- 记录恢复时间与可恢复数据时点，判断是否满足 RTO/RPO。

### 10.3 发布与回滚

- 开发 → 集成测试 → 预发布验证 → 教育试点 → 分批接入其他业务线。
- 应用、数据库迁移、模型/提示词配置、索引版本都可追踪。
- 发布前运行固定回归题和权限测试；不通过时阻止扩大范围。
- 新模型或检索策略先对照评估，再小范围验证，异常可回退上一套有效配置。
- 索引回滚与文档有效版本一致；回滚后仍执行最新撤权和删除规则。
- 提供变更清单、发布记录、回滚步骤和故障处置手册。

## 11. 效果评估与回归

### 11.1 评估集

首期建议准备 150 道人工核对问题：教育约 100 道、金融约 20 道、其余领域各约 10 道；开发集约 90 道、冻结测试集约 60 道。该规模用于首轮验证，扩大业务覆盖后增加评估样本。

样本记录问题类型、答案要点、是否可回答、文档与版本、原文证据、适用条件及预期行为。覆盖事实查询、精确术语、跨文档综合、资料不足、版本冲突、领域隔离和文档提示注入。

按问题族分组划分；不把测试题、标准答案和标注说明导入业务知识库。模型辅助标注与裁判需要人工复核。

### 11.2 评估指标

分别统计检索命中与证据覆盖、答案正确率、引用支持率与覆盖率、资料不足处理正确率、过度拒答率，以及各阶段延迟与成本。报告各业务线分项结果，不能只给总体平均数。

四组基础实验：Milvus BM25 与选定 Profile 稠密检索、稠密与稠密 + BGE 稀疏混合检索、开启/关闭 GPU BGE-Reranker-Large、固定长度与结构化切分。固定其余配置，记录改进、退步样本和代价。

不再进行多模型嵌入选型实验。P1 图谱扩展开关实验固定 BGE-M3 与其他链路配置，比较关系问题证据覆盖、正确率、权限隔离、延迟和资源代价；未实现时按计划标注。

首轮努力目标：Hit@5 ≥ 85%、答案正确率 ≥ 80%、引用支持率 ≥ 90%、引用覆盖率 ≥ 90%、资料不足处理正确率 ≥ 90%。门槛按业务线确认，提供实际分子/分母，未达标项形成整改或试点范围限制。

详细评估口径、对照实验与样本要求见 [配套评估计划](./项目面试与评估计划.md)。
